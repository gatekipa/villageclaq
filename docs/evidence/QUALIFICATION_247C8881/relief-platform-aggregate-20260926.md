## Before and repair

The platform `admin` role's service-role query allowlist included `relief_claims`; `/api/admin/query` accepted arbitrary flat claim columns, and the Relief report requested claim ID, membership ID, amount, event type, status and timestamp. `/api/admin/export` sent one row per claim. A configured service-role key would bypass the R-011 row policy and expose these rows to staff without separate operational claim-detail permission. The isolated local server's service-role key is a placeholder, so this was a demonstrable code/authorization path, not a before-browser disclosure claim.

`00179` adds plan-level counts and amounts with separate pre-aggregation for enrollments, claims and payouts. It is an invoker RPC executable only by `service_role`. `00180` adds a fixed-window, current-staff-scoped wrapper for active platform `admin`/`super_admin`; it checks `auth.uid()` from the current JWT, has no free-form cutoff, and returns no claim/claimant ID, event type, narrative or claim timestamp. The generic service-role query now rejects `relief_claims` for all roles. Relief reporting, usage/engagement counts and aggregate CSV consume the scoped wrapper; the export returns only after its platform audit insert succeeds. Operational claim readers continue to use their current RLS policies.
