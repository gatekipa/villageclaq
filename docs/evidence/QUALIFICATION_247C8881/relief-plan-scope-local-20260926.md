## Approved contract and change

Master PRD [R-002/R-003](https://github.com/gatekipa/villageclaq/blob/050be86c9df3455c66b27bb5853eb786228b4009/docs/VILLAGECLAQ_MASTER_REBUILD_PRD_V1.md) requires explicit plan ownership, operational financial owner, participation, collection/review/payout authority, reporting audience, effective dates, and one local-to-global hierarchy model. `00151` records these as private versioned scope rows with server-authorized, request-bound changes. The current F3 posting adapter uses `relief_plans.group_id` as ledger owner, so the contract currently requires that group as the financial owner; a different owner requires the pending R-006 adapter, never silent redirection. Existing S0/M2 plan ownership is **not** guessed or backfilled.

`00152` binds newly inserted Relief payments to the effective plan-scope version and checks both participation and collection scopes. A frozen membership snapshot prevents a later hierarchy move from silently changing the scope; a topology change requires an explicit new scope version before new receipts. A pre-contract pending payment cannot silently become confirmed after scope activation. `00153` creates a new plan and first scope in one transaction with an immutable create intent; direct ordinary plan INSERT is denied. `00154` prevents a contracted plan's owner, currency or sharing flag from changing outside the scope contract. The plan form now uses the current group currency and offers unit, subtree or organization participation selection. Its card distinguishes a configured scope from a legacy plan whose scope is pending or has stale topology. UI selects the current plan owner for review and payout; distinct delegated authorities are represented in the model but need R-005/R-006 integration.

`00155` gates the existing branch rollup for contracted plans on a current topology, active membership inside the frozen reporting audience, and a current `reports.view` grant for the branch unit. Uncontracted S0/M2 plans retain the prior report path pending R-012 classification. This is the report audience gate, not the full R-010 inter-unit management projection.

`00156` makes the currently designated review unit authoritative for the claim decision RPC, claim-detail SELECT policy, and immutable decision-history reader. A permission loss or stale topology denies replay. The claimant's own history access remains. Legacy uncontracted plans retain the qualified owner-group check until R-012 cutover.

`00157` refuses a delegated payout-unit scope until the branch-agent payout adapter exists. For owner payouts, the command checks the current topology and owner financial authority on retries. A new payout requires an active restricted fund chosen explicitly and writes that fund into the canonical F3 posting. A previously paid claim can recover its original category/fund from the stored F3 payload when an older caller omitted `fund_id`; a changed supplied fund conflicts. The claim dialog now requires a restricted fund in EN/FR. This owner-payout slice does **not** implement delegated branch payout economics.
